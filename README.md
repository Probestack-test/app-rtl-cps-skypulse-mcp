# SkyPulse MCP

An MCP (Model Context Protocol) server generated by ForgeSphere from an API specification. It exposes 1 tool over the Streamable HTTP transport at `/mcp`.

| | |
| --- | --- |
| Language | TypeScript (Node.js 22) |
| Version | 1.0.0 |
| Authentication | OAuth 2.0 (client credentials) |
| Target API | https://api.open-meteo.com/v1 |
| Deployment | Google Cloud Run (`.github/workflows/ci-cd.yml`) |

## Run it

Set the environment variables listed in `.env.example`, then:

```bash
npm install
npm run build
npm start
```

## Authentication

The server issues short-lived access tokens itself. Nothing secret is stored in this repository: `MCP_OAUTH_CLIENT_ID`, `MCP_OAUTH_CLIENT_SECRET` and `MCP_OAUTH_SIGNING_KEY` come from the environment, and the server will not start without them.

```bash
# 1. get a token
curl -s -X POST "$BASE_URL/oauth/token" \
  -d grant_type=client_credentials -d client_id="$CLIENT_ID" -d client_secret="$CLIENT_SECRET"

# 2. call the MCP endpoint with it
curl -s -X POST "$BASE_URL/mcp" \
  -H "Authorization: Bearer $ACCESS_TOKEN" -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

## Connect an MCP client

```json
{
  "mcpServers": {
    "skypulse-mcp": {
      "url": "https://<your-service-url>/mcp",
      "headers": { "Authorization": "Bearer <access token>" }
    }
  }
}
```

## Tools

| Tool | Calls | Description |
| --- | --- | --- |
| `skypulse_get_forecast` | `GET /forecast` | Get weather forecast for any location |

Request bodies are sent as JSON. Path, query and header parameters are arguments of the tool; credentials for the target API come from the environment, never from the caller.

## Tests

- Unit tests (`npm test`) run against a stub of the target API and are part of the CI workflow.
- A Postman collection in `postman/` calls the MCP endpoint (positive, negative, performance tests). Import it and fill in the `clientId` and `clientSecret` collection variable(s).

## Deployment

Pushing to `feature-adarsha` or `release` builds, tests and deploys the server to Cloud Run.

The credentials the server accepts (`MCP_OAUTH_CLIENT_ID`, `MCP_OAUTH_CLIENT_SECRET`, `MCP_OAUTH_SIGNING_KEY`) start as values generated for this bundle: the deploy workflow uses them, and so does the Postman collection, so the first deploy needs no setup. For real use, add a repository **secret** of the same name (it always takes precedence) and stop using the generated value.

Optionally set the repository variable `UPSTREAM_BASE_URL`.
